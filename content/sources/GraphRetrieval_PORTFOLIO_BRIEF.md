## 4. Problem
LLM agents answering clinical questions over FHIR records must follow `reference` links between resources, but the benchmark's tools only fetch whole types or one ID per call [code/FHIR-AgentBench/tools/resource_tools.py:12-47]. The best published agent reaches 0.5004 answer correctness overall and 0.1391 on Medication questions [papers/01-core/2509.19319_FHIR-AgentBench.pdf, Table A3, p. 14].

## 5. How it works
Upstream harness (pinned submodule, not yet run here); paths under `code/FHIR-AgentBench/`.
1. `run_agent.py` hands one benchmark question to a worker [run_agent.py:208].
2. The agent asks the LLM through litellm [utils/core_utils.py:356]; its tool sends `{Type}?patient={id}` and follows pagination [tools/resource_tools.py:36-37, fhir_client.py:70].
3. An LLM judge and retrieval recall/precision score the run [evaluation_metrics.py:74, :463-465].
